# 제출 전 점검

## 작업 종료 약 25분 전: 확인 질문 대비

Codex에 한 번 요청한다.

```text
지금 저장소(코드, git log, docs/)를 보고 작성자가 결과물을 이해하는지 확인하는 질문 6개를 만들어 줘.
설계 선택 이유, 데이터 가정, 예외·장애, 검증 방법, 한계, 요구 변화 각 1개. 질문만 보여 줘.
```

답은 AI 없이 아래 틀로 내가 정리한다.

### 답변 틀

1. 결론: 무엇을 왜 그렇게 했는지 한 줄
2. 근거: 합의문 항목이나 데이터 수치
3. 약점: 내 코드·가정의 구체적 약점 하나
4. 파급: 그 약점이 터지면 무엇이 틀리는지
5. 다음 검증: 무엇을 확인하고 어떻게 고칠지

- 질문의 전제가 실제 구현과 다르면 그 차이부터 밝힌다.

## 작업 종료 10분 전: 제출

- [ ] 과제 README가 요구한 파일명·경로가 맞다
- [ ] 실행 명령 한 줄로 처음부터 다시 돌려 봤다
- [ ] docs/HANDOFF.md에 성공 기준별 결과, 검증, 남은 한계, 외부 자료 출처가 있다
- [ ] git status가 깨끗하고 마지막 커밋이 있다
- [ ] 열린 파일이 모두 저장됐고 충돌 표시가 없다
- [ ] 제출 미리보기를 확인한 뒤 확정한다 (확정 후에는 수정할 수 없다)
