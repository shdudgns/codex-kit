# Codex 프롬프트 예시

Codex 하나로 구현과 프롬프트 설계를 함께 하는 환경을 전제로 한다.

## 원칙

- 담당자에게 물을 질문 초안은 내가 먼저 쓴다(`interview.md`). 처음부터 "무엇을 물어야 하나"를 Codex에 맡기지 않는다.
- Codex는 데이터를 직접 확인해 근거 있는 질문을 뽑고, 내 초안에서 빠진 질문을 채우는 데 쓴다.
- Codex가 낸 질문은 담당자가 쓰는 현업 말로 바꿔서 보낸다.
- 담당자 답을 매번 Codex에 옮기지 않는다. 들은 내용은 `docs/AGREEMENT.md`에 적고, Codex는 그 파일을 읽게 한다.
- 채택·수정·거절한 Codex 제안은 `docs/DECISIONS.md`에 이유와 함께 한 줄 남긴다.

## A. 데이터 확인 → 담당자에게 물을 질문

```text
docs/skills/data-check/SKILL.md 절차대로 data/ 아래 데이터 파일을 확인해 줘.
파일은 만들거나 고치지 말고, 결과를 표로만 보여 줘.
마지막에 "담당자에게 확인할 데이터 질문" 3~5개를 근거 수치와 함께 적어 줘. 해법은 제안하지 마.
```

## B. 내 질문 초안의 빈 곳 찾기

```text
담당자에게 보낼 질문 초안이야: (내 질문)
지금까지 들은 것: (요약 2~3줄)
누가·언제·무엇을 결정하는지, 성공 기준, 데이터 예외 기준으로 빠진 질문만 2~3개 추가해 줘. 해법은 제안하지 마.
```

## C. 합의문 모호점 점검

```text
docs/AGREEMENT.md를 읽고, 이대로 구현하면 네가 임의로 정하게 되는 부분(정의, 경계값, 예외, 출력 형태)을 목록으로만 보여 줘.
```

## D. 계획 요청

```text
docs/AGREEMENT.md의 성공 기준을 만족하는 구현 계획을 단계별로 보여 줘.
단계마다 바꿀 파일, 실행 명령, 확인 방법을 적고, 아직 구현하지 말고 승인을 기다려.
```
