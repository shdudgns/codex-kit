# 데이터 확인

## 처음 읽을 때

1. 파일별 행·열 수, 컬럼 이름과 타입, 앞 3행을 출력한다.
2. 컬럼별 결측 수와 비율, 고유값 수, 수치 컬럼의 최소·중앙값·최대를 출력한다.
3. 키 후보 컬럼의 중복 수를 센다.
4. 시간 컬럼이 있으면 시작·끝, 간격, 빠진 구간을 확인한다.
5. 정답(라벨) 컬럼이 있으면 클래스 비율을 출력한다.
6. 이상해 보이는 값(음수 수량, 범위 밖 값, 단위가 의심되는 값)은 목록으로 보여 주고 처리 방법을 묻는다.

확인한 가정은 docs/DECISIONS.md의 "데이터 가정"에 적는다.

## 파일 간 대조 (파일이 여러 개일 때)

1. 같은 정보가 두 파일에 있으면(소속, 시간대, 코드, 날짜 등) 서로 다른 행의 수와 예시 3개를 출력한다.
2. 참조 키(다른 파일의 ID를 가리키는 컬럼)가 대상 파일에 모두 있는지 센다. 없는 키 수와 예시를 출력한다.
3. 파일마다 기간(시작·끝)을 출력하고 서로 맞는지 본다.
4. 상태·코드 컬럼의 값 목록과 건수를 출력한다. 문서에 없는 값은 담당자 질문 후보로 표시한다.
5. 쌍으로 있어야 하는 데이터(모든 조합, 양방향 등)는 빠진 쌍 수를 센다.

차이는 고치지 말고 건수와 함께 보고한다. 어느 쪽을 따를지는 담당자 확인 후 docs/DECISIONS.md에 적는다.

## 제조 데이터일 때 (로트 이력, 장비 센서, 수율, 테스트 결과)

1. 제품·레시피별 기준선을 먼저 구한다. 제품이 섞인 평균으로 장비를 비교하지 않는다.
2. 특정 제품만 쓰는 장비가 있는지 센다. 있으면 장비 효과와 제품 효과가 섞인다.
3. 측정 장비(테스터·계측기) 문제와 공정 문제를 나눈다. 같은 시기 측정 장비끼리 비교하고, 재측정 행이 있으면 어느 값을 쓸지 정한다.
4. 원인이 생긴 시각(공정 처리 시각)과 결과를 잰 시각(테스트 시각)을 구분한다. 시간대(UTC/KST)도 확인한다.
5. 여러 장비의 값이 같은 날 같은 배수로 바뀌면 장비보다 기록 방식(단위·시스템 변경)을 먼저 의심한다.
6. 장비·챔버가 많으면 하나쯤은 우연히 나빠 보인다. 정비(PM)·레시피 변경 같은 이벤트 전후를 같은 장비 안에서 비교하고, 센서·불량 유형 같은 다른 증거로 교차 확인한다.
7. 영향 규모는 %p, 웨이퍼 수, 로트 수, 시간으로 보고한다.

## 가공할 때마다

- 단계 전후의 행 수와, 빠진 행의 이유별 개수를 출력한다.
- 병합(join)은 전후 행 수와 짝을 못 찾은 키 수를 출력한다. 행이 늘면 중복 키를 의심한다.
- 원자료에서 3행을 골라 결과와 직접 대조하고, 어떤 행을 골랐는지 출력한다.

## 모델·예측을 만들 때

- 시간 순서가 있으면 시간 기준으로 나눈다. 미래 정보가 학습에 섞이면 안 된다.
- 예측 시점에 알 수 없는 컬럼, 정답에서 파생된 컬럼은 입력에서 뺀다.
- 정답이 불균형하면 정확도 대신 담당자 기준에 맞는 지표(재현율, 정밀도, F1 등)를 쓴다.

## 보고

- 숫자는 코드 출력에서만 인용한다. 표로 보여 주고, 해석은 따로 적는다.
