# 배포 전제 웹 서비스 뼈대

과제 README가 요구한 것만 만든다. 아래는 빠뜨리기 쉬운 항목의 점검표다. 기술 스택은 과제가 정한 것을 따르고, 정하지 않았으면 내가 설명할 수 있는 가장 단순한 것을 고른다.

## 1. 설정과 비밀값

- 포트, DB 접속 정보, 초기 계정 비밀번호, 세션 키 등은 환경변수로 받는다. 코드에 기본 비밀값을 쓰지 않는다.
- `.env.example`에 변수 이름과 예시 값을 둔다. 실제 `.env`는 커밋하지 않는다.
- 서버는 0.0.0.0에 바인딩한다. 시간 계산은 시간대를 코드에서 명시한다(컨테이너 기본값은 UTC일 수 있다).

## 2. DB

- 서비스 시작 시 스키마가 없으면 만든다. 초기 계정과 기본 입력 묶음을 넣는다(이미 있으면 건너뜀).
- DB 파일이나 볼륨 경로는 환경변수로 받는다. 재시작 후에도 데이터와 결과가 남는지 직접 확인한다.

## 3. 헬스체크와 컨테이너

- 헬스체크 경로는 서비스와 DB 연결 상태를 짧게 돌려준다.
- Dockerfile은 의존성 설치 → 코드 복사 → 환경변수로 포트 받기 순서. 빈 환경에서 처음부터 빌드해 본다.

## 4. 역할과 로그인

- 역할마다 할 수 있는 일을 표로 먼저 정한다. 서버 쪽에서 역할을 검사한다(화면에서 버튼만 숨기지 않는다).
- 비밀번호는 해시로 저장한다. 초기 계정 정보는 환경변수로 받고, 실행 문서에는 변수 이름과 확인 방법만 적는다.

## 5. 입력 묶음: 선택 → 검증 → 적용

- 준비된 입력 묶음 목록을 화면에서 고른다(파일 업로드·선택창이 금지되면 서버 폴더 목록으로).
- 검증은 실제 파일을 읽어서 한다: 필수 열, 형식, 값 범위, 참조 키, 중복, 쌍 완전성. 오류는 파일·행·열·값·이유로 모아 보여 준다(첫 오류에서 멈추지 않음).
- 검증에 실패하면 적용하지 않는다. 기존 데이터와 결과를 그대로 둔다.
- 적용은 한 트랜잭션으로 한다. 현재 적용된 묶음 이름과 적용 시각을 화면에 보여 준다.
- 결과에는 어떤 입력 묶음과 설정값으로 계산했는지 기록한다. 현재 묶음·설정과 다르면 '재계산 필요'로 보여 주고 옛 결과를 새 결과처럼 보여 주지 않는다.

## 6. 내보내기

- 과제가 정한 형식을 필드명·타입·시간 형식까지 그대로 맞춘다. 형식 정의 문서와 대조하는 테스트를 둔다.
- 저장창이 금지되면 화면 표시·복사, 또는 서버 폴더 저장 + 경로 안내로 한다.

## 7. 확인 순서 (마지막 15분)

빈 DB 시작 → 빌드 → 역할별 로그인 → 오류 입력 적용(거부·유지 확인) → 정상 변경본 적용 → 재계산 → 내보내기 → 검증기 → 재시작 후 유지 → 헬스체크.
